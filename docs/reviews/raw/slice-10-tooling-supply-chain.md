[CRITICAL] [SECURITY] /Users/robertogarcia/src/clericot/cmd/clericot/main.go:327 — Every scaffolded module accepts `tenant_id` from the untrusted request body, replicating a cross-tenant write primitive into all future modules.
- **Issue:** The generated `handler.go` template declares `TenantID string \`json:"tenant_id"\`` in `Create<X>Input.Body` (lines 289–293) and then does `tenantID := input.Body.TenantID`, falling back to `tenant.FromContext(ctx)` only when the body field is empty. The RLS policy in `sql/migrations/0002_rls.sql` then *authorizes* the write, because RLS trusts the session GUC. The hand-written module this is supposedly modeled on does the opposite: `internal/modules/orders/service.go:61` derives the tenant exclusively from `platformAuth.PrincipalFromContext(ctx).TenantID` and `orders/handler.go` has no `tenant_id` field at all. ### Strengths

- The migration/tenancy *SQL* is genuinely well built: `0002_rls.sql` uses `FORCE ROW LEVEL SECURITY`, correctly wraps the `DO $$ ... $$` role-creation block in `-- +goose StatementBegin/End` per the documented parser trap, defines a permissive `FOR ALL TO app_user` base policy (avoiding the restrictive-only DENY-ALL pitfall), and applies `ALTER DEFAULT PRIVILEGES` so future tables inherit grants.
- `env.Parse` with nested `envPrefix` structs gives a genuinely clean, reflection-light config surface with no global state, and `Load()` returning `(*Config, error)` rather than panicking is the right shape — it just needs a `Validate()` hung off it.
- The CI lint step installs golangci-lint via `go install` on the runner rather than downloading a prebuilt binary. The stated rationale is incomplete (see the finding above), but the resulting behavior — building the linter with the same toolchain that builds the project — is the right instinct and avoids a whole class of confusing failures.
- The scaffolder's generated `mapDomainError` is a good pattern to propagate: it checks `errors.As(err, &prob)` for an already-typed `*httperr.Problem` before falling through to sentinel matching and `httperr.Transform`, which keeps RFC 9457 mapping in the transport layer and out of the domain, exactly as `project-layout.md` §3 requires.
- `docker-compose.yml` gives every stateful service a real healthcheck (`pg_isready`, `redis-cli ping`, `mc ready local`) with sensible intervals, so `depends_on: condition: service_healthy` is available to anyone who needs ordering.

### Out-of-slice observations

- `internal/platform/tenant/middleware.go:18-23`: the `X-Tenant-ID` header is accepted **unvalidated when `principal == nil`** — the `HasTenantAccess` check is guarded by `principal != nil`, so an anonymous request carrying `X-Tenant-ID: victim` sets the tenant context unchallenged. This is the platform-level twin of the critical scaffolder finding.
- No `huma.Operation` anywhere in the repo declares a `Security:` entry, and no `SecuritySchemes` are registered on the API; `TokenService.HTTPMiddleware` only *attaches* a principal and never rejects, so authentication is enforced solely by ad-hoc `PrincipalFromContext(ctx) == nil` checks inside individual services.
- `internal/modules/orders/service.go:207` discards the audit-staging error with `_ =` inside `CancelOrder`, while the same call is error-checked in `CreateOrder` at line 137 — an inconsistent compliance guarantee for the same audit trail.
- Seven separate test packages each declare their own `TestMain` spinning up independent Postgres + Redis testcontainers; `go test ./...` runs packages concurrently, so a 4-vCPU runner can be asked for up to 14 containers at once under `-race` with the default 10-minute per-package timeout and no `-p` limit in CI.
